Proof-of-concept design specification

MWB

A work assistant for Windows. It types what you say, keeps track of your meetings, helps with email and code, and writes your end-of-day journal. Speech runs on your laptop; for now the writing goes through an API key, so it needs almost no memory. It is sized for the 16 GB laptop you have today and scales up when you get a better one.

1Features

  • Wispr-style dictation. Double-tap Caps Lock, talk, and the text appears in whatever app you are typing in. On this laptop a 5-second phrase is transcribed in 0.91 s.
  • Ask by voice. The same double tap answers questions about your day, or anything else, in a small card.
  • A floating indicator with eight skins or your own images. Double-tap Alt to show or hide it.
  • The speech engine from AI-App: NVIDIA Parakeet TDT 0.6B v2 (int8), with whisper.cpp for Hindi and Hinglish.
  • Automatic meeting capture in any video-call app: Teams, Zoom, Google Meet, Webex, Slack and others, desktop or browser. You and the other side are recorded on separate lanes.
  • Work or Timepass. Every meeting gets a label, a reason and a time split, and the labels improve from your corrections.
  • Email help. Explains a selected email and drafts replies in your style. It never sends anything itself.
  • Code help. Explains and optimises selected code in any editor or browser.
  • End-of-day journal with commits and their SHAs, meetings, email, notes and time per project, ready at 18:30.
  • About 40 MB at idle. Models run in separate processes that start when needed and exit when idle.
  • Speech local, writing through an API for now. Speech runs on a model already installed on this laptop, and audio never leaves it. Notes, email, code and the journal go to an API (Groq, as in AI-App), so they need almost no memory. Qwen3.5, downloaded on 12 October, is kept in sync on this laptop as the fallback, and any skill can be set to local-only.
  • Effort you set per device. Four hardware profiles and four effort levels. On a new laptop a setup screen suggests a level and you choose.

2Applications

  • Daily stand-up and status updates
  • Timesheets and weekly reports
  • Meeting notes and action items
  • Email triage and replies
  • Quick code explanations and reviews
  • A lighter replacement for Wispr Flow, with speech recognised on the laptop

3Description

MWB is a Windows tray assistant designed so that nothing heavy stays in memory. A small core process is always running. It owns the hotkeys, the tray icon, the meeting detector, the data collectors and the database.

Speech runs in a separate worker process. It starts when you start talking or a meeting begins, and exits after it has been idle for a while. Ending the process is the only reliable way to give memory back to Windows. Language work goes to an API for now; when the API can't be used, a local language worker starts and exits the same way.

This specification is based on an audit of your HP EliteBook 840 G8, a review of the AI-App code, and benchmarks run on this laptop. Sections 4 to 6 report what was found. Sections 7 to 16 define what to build. Sections 17 to 19 cover the plan, the risks and the decisions that are yours. If a term is new to you, section 20 explains it. To see the UI and these flows in action, open the interactive demo.

4.2Where the memory goes

Two browsers and the Claude app hold about 9 GB between them. Wispr Flow holds 1.5 GB all day for a single job, dictation. MWB has to do far more than that job and still stay under Wispr Flow's line for most of the day. Figure 11.2 shows how.

4.3Findings

Finding 1 · cheapest speed-up

The only memory stick is a Crucial CT16G4SFRA32A (16 GB DDR4-3200) in one of two slots, so memory runs single channel. A matching second stick gives 32 GB and dual channel at 51.2 GB/s. Local LLM output speed is limited by memory bandwidth, so it roughly doubles. The integrated graphics also get the dual-channel memory Intel specifies for full Iris Xe performance. HP lists the 840 G8 at up to 64 GB (2 × 32 GB). On a managed laptop this needs IT's approval.

Finding 2 · replace, don't stack

Wispr Flow is running as 11 processes holding about 1.5 GB. MWB's dictation is built to replace it. Running both doubles the memory cost, and the two apps would compete for the microphone and for hotkeys.

Note · Python

The python command on the PATH is the Microsoft Store placeholder and prints "Python was not found". Python 3.14.7 is installed and works through the launcher as py -3.14. Its standard library already includes SQLite 3.50 with full-text search (FTS5) and Tkinter 9.0. MWB uses both, so the always-on core needs very few extra packages.

5.2Leave behind

  • The Electron shell. A Chromium-based app needs 150 MB or more before it does any work; Wispr Flow shows where that ends up. MWB's always-on part is a small Python tray process, and windows open only when you ask for them.
  • The overlay features: the always-on-top window excluded from screen capture, the custom pointer, OCR screen-ask and auto-answer. MWB is a visible assistant, and a meeting recorder has to show that it is recording.
  • Any borrowed identity in packaging. MWB ships under its own name and icon. On a managed laptop, an audio-capturing process that presents itself as a different product is exactly what endpoint security flags.

6.4What the numbers decide

  1. Dictation uses 4 threads. You are waiting for the text, and 4 threads cut a 3-second phrase from 1.66 s to 0.66 s.
  2. Meetings use 2 threads at below-normal priority. The call app, whichever it is, needs the CPU during a call, and 2 threads still run 4.4× faster than real time.
  3. Never send more than about 10 seconds of audio at once. Cutting the 62-second file into 10-second pieces was faster (10.8 s against 12.5 s) and used 530 MB less.
  4. Background meeting work runs with the onnxruntime arena off. Memory stays flat at 0.99 GB, at a cost of about 20 % more time. Dictation keeps the arena on for speed, and the process is recycled after 15 idle minutes.
  5. Start loading the model when the hotkey goes down. Loading takes 7.5 to 12 s and a typical phrase lasts 3 to 8 s, so most of the wait hides behind your speech.
  6. Keep whisper.cpp only for Hindi and Hinglish. On English, Parakeet was 1.7× faster and made no recognition errors where whisper base.en made two. The multilingual small model, measured on 12 October, is slower again on English (2.6× real time, 4.2 % WER) and needs 1.06 GB, so it runs only for Hindi and Hinglish, in the background. Large-v3-turbo, downloaded on 12 October, is slower than real time here (0.45×), so on this laptop it is only for overnight re-runs.
  7. Keep numpy and onnxruntime out of the always-on process. Python starts at 16 MB. Importing those two libraries costs about 250 MB before any model loads.

7.3Hard limits

Never
  • Never sends an email or a message. MWB writes drafts only.
  • Never uploads audio. The API receives text only, and never the text of a skill set to local-only.
  • Never records without the tray turning orange and a notification on screen.
  • Never logs keystrokes, takes screenshots or reads browser history.
  • Never loads two models at the same moment on the Lean profile. Two can stay resident together only when the memory guard finds room; otherwise the idle one exits first.
  • Never exceeds 3.5 GB in total on the Lean profile. The memory guard defers work instead.

8Architecture

8.1Design principles

  1. A small core that is always on, and disposable workers for heavy work. On Windows, ending a process is the only dependable way to return its memory.
  2. Speech local, language through an API for now. Audio never leaves the laptop. Language work goes to an API so it needs almost no memory, and a local model kept in sync takes over when the API can't be used. Any skill can be set to local-only, and MWB shows exactly what it sends.
  3. Facts by code, prose by model. SHAs, durations, counts and names come straight from the database. The model writes only the narrative, and each sentence must cite the events it describes.
  4. Every engine behind an interface. Swapping Parakeet for Granite Speech, the API for a local model, or a 2B model for a 9B one, is a configuration change.
  5. Visible and in your control. Tray state, a recording indicator and one key that pauses everything.
  6. Effort follows the hardware. The same build works harder on a stronger machine, and moving it to another laptop re-tunes it on first start (§12.5, §12.6).
  7. No vendor lock-in for calls. Any app that holds the microphone can be a meeting; a registry file names the known ones (§9.3).

8.6The running loop

MWB does not spin in a loop checking things all the time. The core spends almost all of its life asleep inside one Windows message loop. It wakes only when something happens: a key tap, a hotkey, a timer, a power or audio-device change, or a click on the tray icon. Each wake-up takes microseconds, so the core uses close to 0 % CPU while you work. Heavy work never runs inside the loop; the loop hands it to a background thread or a worker process and goes straight back to sleep.

One round of use, from a double tap of Caps Lock to text in your app or an answer on screen, goes through the steps below. The details are in §9.1 and §9.7.

9.1Dictation

The goal is Wispr Flow's feel without its memory cost: double-tap Caps Lock, talk, and the text is already there when you stop. The trick is to transcribe while you are still talking, so that when you finish only the last couple of seconds are left.

  1. Start. Double-tap Caps Lock to talk hands-free, or hold Ctrl+Alt+Space for push-to-talk. The core starts recording the mic into a ring buffer straight away, so the first word is never lost, and the indicator wakes up (§13.3). If the speech worker is not running, the core starts it now.
  2. While you talk. Voice-activity detection cuts the audio at pauses of 500 ms or more, into pieces of at most 10 s, and sends each piece to the worker as soon as it closes. With live words on, the indicator shows the last few words.
  3. Finish. Double-tap Caps Lock again, stop talking for 2 s, or let go of the push-to-talk keys; Esc cancels. The last piece goes to the worker at once. MWB waits until Ctrl, Alt and Caps Lock are released, so its paste never arrives as Ctrl+Alt+V, and Caps Lock ends in the state it started in.
  4. Write or answer. If the cursor is not in a text box, or you began with the wake word ("MWB, what's my next meeting?"), your words become a question for answer mode (§9.7). With text selected, a command such as "make this shorter" rewrites the selection (§9.2). Otherwise MWB writes.
  5. Clean-up rules, under 5 ms: drop fillers, collapse stutters, turn spoken commands into punctuation, apply your dictionary. Parakeet already outputs punctuation and capitals.
  6. Optional polish by a language model, chosen per app. Through the API it adds under a second; on the local fallback, 1 to 3 s. It is off by default on the Lean profile, because it sends what you dictated to the API; hold Shift as you finish to ask for it.
  7. Insert. Save the clipboard, put the text on it, send Ctrl+V, and restore the clipboard 300 ms later. Apps that block paste get the text typed with SendInput instead.
  8. Log the text, target app and latency to the history table, for search and re-insert.

9.3Meetings

Any video-call app, desktop or browser. Detection does not depend on one vendor. Every 5 seconds the core asks Windows which apps are using the microphone right now. Windows records when each app last started and stopped using the mic, both for packaged apps such as new Teams or WhatsApp and for desktop programs such as Zoom.exe or slack.exe. A stop time of 0 means the app is using the mic at this moment. Reading these keys takes microseconds and needs no admin rights. On this laptop, keys already exist for new Teams, Edge and Wispr Flow.

sensors/meeting_detector.py (sketch)
import winreg

MIC = r"Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\microphone"

def mic_holders() -> list[str]:
    """Every app using the microphone right now, packaged or desktop."""
    found = []
    for path, packaged in ((MIC, True), (MIC + r"\NonPackaged", False)):
        with winreg.OpenKey(winreg.HKEY_CURRENT_USER, path) as root:
            for i in range(winreg.QueryInfoKey(root)[0]):
                name = winreg.EnumKey(root, i)
                if name == "NonPackaged":
                    continue
                with winreg.OpenKey(root, name) as k:
                    try:
                        start = winreg.QueryValueEx(k, "LastUsedTimeStart")[0]
                        stop = winreg.QueryValueEx(k, "LastUsedTimeStop")[0]
                    except FileNotFoundError:
                        continue
                if start and stop == 0:                  # 0 = still using the mic
                    # desktop apps are keyed by exe path with "#" for "\"; keep the exe name
                    found.append(name if packaged else name.split("#")[-1])
    return found   # e.g. ["MSTeams_8wekyb3d8bbwe"], ["Zoom.exe"], ["brave.exe"]

Each holder is matched against config/vc_apps.yaml. When the holder is a browser, MWB reads the browser's tab titles through UI Automation, only at that moment, and looks for a known meeting site. 11.2Memory guard

  • Before loading a model, the core checks free physical memory with GlobalMemoryStatusEx. It needs the model size plus a 1 GB margin.
  • If memory is short, it tries in order: stop idle workers, pick the next smaller model in the profile, then defer batch work until memory frees up. Language work rarely needs this, because it goes to the API unless the API can't be reached.
  • One model loads at a time. Two may stay resident together only when there is room for both.
  • Idle timers: the speech worker exits 15 minutes after the last dictation, or when its meeting job ends. The language worker exits 5 minutes after its last job on Lean, 30 minutes on Balanced.
  • When free memory stays under 1 GB for 30 s, idle workers exit at once.

12Profiles, effort and models

The same code runs on every machine. A profile decides which models it uses, how many threads they get and what stays warm. An effort governor decides how hard MWB works from minute to minute (§12.5), and MWB re-tunes itself when you move it to another laptop (§12.6).

12.1Detection and calibration

  1. Probe at start-up: total and free RAM, number of memory sticks and their speed (which gives bandwidth), GPU and VRAM (DXGI, plus nvidia-smi when present), any NPU (device class ComputeAccelerator), CPU features such as AVX-512 VNNI, and the power source.
  2. Calibrate once, in about 60 s, and again whenever the hardware changes: speech speed on a bundled clip, the API's response time, tokens per second for the local fallback model on a fixed prompt, and typical free memory.
  3. Pick a profile and write it to the config. You can override it, for example profile = "lean".
  4. Choose models from models.yaml, which lists candidates for each capability, best first. The first one that fits the profile and passes the memory guard wins.

12.3Why the second memory stick matters

Writing each token means reading the whole model from RAM once, so tokens per second is at most usable bandwidth divided by model size. You choose the level

On every new device, a setup screen shows what MWB found and pre-selects the suggested level. You can keep it or pick another. You decide four things: a fixed level, or automatic adjustment within a range you set; what happens on battery; a different level for any feature, for example High for the journal and Balanced for dictation; and whether to download the models your choice needs now or later. How automatic adjustment works

  • Suggested level by profile: Lean E2, with E3 for the night pass; Balanced E3; Performance and Workstation E4. This is only the starting point on the setup screen.
  • Down, when automatic is on: one level on battery and two below 30 % charge; one level when the CPU stays above 80 % for 30 s or free memory drops below 2 GB. It never goes below the lowest level you set.
  • Up, when automatic is on: one level when on AC power, idle for 10 minutes and with room in memory, never above the highest level you set.
  • Fixed level: the rules above are off, except the memory guard (§11.2), which still defers work rather than let MWB run out of memory.

How the local model is kept in sync

  1. One set of prompts, one output check. Each skill has a single prompt template and a single JSON schema. The citation validator and the SHA check run on answers from both routes.
  2. One contract. The API and llama-server both speak OpenAI-compatible chat completions, so the router changes only the address and the model name.
  3. A sync check. Ten saved test prompts, one or two per skill, run through both routes in Phase 0, after any change to a prompt or a model, and once a week on AC power. If the local answer breaks the format, misses a fact or is too slow, the Today page says so.
  4. Automatic fallback. When the API fails (no network, no answer within 10 s, a rate limit or a bad key), the same request goes to the local model if the memory guard allows it. Otherwise it waits in a queue and MWB tells you.
  5. Local-only skills. Any skill can be set to local-only in Settings, and its text then never leaves the laptop. Learning your email style starts that way, because it reads 30 sent emails at once.
  6. Going local later. On a laptop with more memory, moving a skill to the local route is one setting, and the local model can grow to Qwen3.5 9B.

13.1How the keys are wired

  • No keyboard hook. Shortcuts are registered with the Win32 RegisterHotKey call and MOD_NOREPEAT. MWB never sees any other keystroke, so Defender has nothing keylogger-like to flag.
  • Double taps. Caps Lock and Alt can't be registered as shortcuts without breaking their normal use, so the core checks the up and down state of only these two keys every 15 ms (GetAsyncKeyState). It cannot see any other key. Two clean taps within 350 ms count as a double tap. Caps Lock is put back to the state it had before the first tap, so the light never ends up changed. A single Alt tap still reaches your app as usual; in Office it briefly shows the key tips, and the second tap hides them again. Phase 0 task P0-2 checks that a 15 ms check catches at least 99 % of taps. If it doesn't, the fallback is a keyboard hook limited to these two keys, after checking with IT.
  • Hold detection. After a hold shortcut fires, the core polls GetAsyncKeyState every 15 ms, only while the key is down, to see when you let go.
  • Conflicts. Each binding has a fallback list and logs [hotkey] ctrl+alt+k could not be registered when another app owns it, the same pattern as AI-App's tryRegister().
  • Starting MWB. Setup adds a Start-menu shortcut with Ctrl+Alt+W as its shortcut key. Windows handles that key itself, which is why it works before MWB is running.
  • AltGr keyboards. On layouts where Ctrl+Alt acts as AltGr, set modifier = "ctrl+shift+alt".
  • Wispr Flow. Turn it off before using MWB dictation, so only one app owns the mic and the push-to-talk keys.

20Glossary

ASR
Automatic speech recognition. Speech in, text out.
WER
Word error rate: the share of words that come out wrong. Lower is better.
× real time (RTFx)
How many times faster than the audio plays. 5× means a minute of speech takes 12 seconds.
VAD
Voice activity detection. Finds where speech starts and stops, so only speech is transcribed.
Diarization
Working out who spoke when, and giving each speaker a label.
Loopback
Recording what your speakers play. In a call, that is the other side.
LLM
Large language model. Reads and writes text: summaries, drafts, labels.
Token
A piece of a word, about three quarters of an English word on average. Model speed is quoted in tokens per second.
Prefill and decode
Reading the prompt, which is fast, and writing the answer, which is limited by memory bandwidth.
Quantization
Storing a model's numbers in fewer bits (int8, 4-bit) so it uses less memory and runs faster, at a small cost in accuracy.
GGUF, ONNX
File formats for models. llama.cpp runs GGUF; ONNX Runtime runs ONNX.
Memory bandwidth, channels
How fast RAM feeds the CPU. Two sticks in two slots (dual channel) double it.
Working set, private bytes
RAM a process has in physical memory right now, against memory it has reserved, part of which may sit in the pagefile.
Arena
onnxruntime's memory pool. Fast, but it keeps memory after a large input instead of returning it.
Worker, sidecar
A separate process that does the heavy work and can be ended to free its memory.
mmap
Mapping a model file into memory, so Windows loads pages as needed and can drop them under pressure.
Few-shot
Putting a handful of examples in the prompt to steer the model, such as your past label corrections.
RAG
Retrieval-augmented generation. Search your own data first, then let the model answer from what it found.
VC app
Any video-conferencing or calling app: Teams, Zoom, Meet, Webex, Slack huddles, WhatsApp and others.
Effort level
How hard MWB works right now, from E1 to E4: threads, model size, extra passes, live features.
Hardware fingerprint
A short ID built from CPU, RAM, GPU and NPU. When it changes, MWB re-calibrates and re-tunes itself.
API key
A password-like token that lets MWB use a cloud model such as Groq or OpenAI. For now, MWB's main route for language work.
Fallback
The local model MWB uses when the API can't be reached, or for a skill set to local-only.
Sync check
Saved test prompts run through both the API and the local model, to make sure the fallback still gives usable answers in the same format.
Thinking mode
Qwen3.5 can reason step by step before it answers. That gives better answers but is much slower on a CPU, so MWB turns it off.
Double tap
Two quick presses of the same key within 350 ms: Caps Lock to talk or ask, Alt to show or hide the indicator.
Indicator
The small floating icon at the bottom of the screen that shows what MWB is doing, like Wispr Flow's pill.
Wake word
A word you start with, "MWB" by default, to make MWB answer instead of typing what you say.
Event loop
The part of the core that sleeps until something happens, handles it in microseconds, and goes back to sleep.
