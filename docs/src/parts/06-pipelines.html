9Pipelines

9.1Dictation

The goal is Wispr Flow's feel without its memory cost: double-tap Caps Lock, talk, and the text is already there when you stop. The trick is to transcribe while you are still talking, so that when you finish only the last couple of seconds are left.

  1. Start. Double-tap Caps Lock to talk hands-free, or hold Ctrl+Alt+Space for push-to-talk. On this laptop another app owns Ctrl+Alt+Space, so MWB registers its fallback, Ctrl+Shift+Alt+Space (P0-2). The mic opens at once, at its own rate, and a 0.4 s pre-roll keeps the first sound, so the first word is never lost. The indicator wakes up (§13.3). If the speech worker is not running, the core starts it now; it also loads when MWB starts, if 2 GB is free.
  2. While you talk. Voice-activity detection cuts the audio at pauses of 500 ms or more, into pieces of at most 10 s, and sends each piece to the worker as soon as it closes. With live words on, the indicator shows the last few words.
  3. Finish. Double-tap Caps Lock again, stop talking for 2 s, or let go of the push-to-talk keys; Esc cancels. A hands-free dictation with nothing said for 10 s cancels itself, and none runs longer than 5 minutes. The last piece goes to the worker at once. MWB waits until Ctrl, Alt, Shift, Win, Caps Lock and Space are all up, so its paste never arrives as Ctrl+Alt+V or Ctrl+Shift+V, and Caps Lock ends in the state it started in.
  4. Write or answer. If the cursor is not in a text box, or you began with the wake word ("MWB, what's my next meeting?"), your words become a question for answer mode (§9.7). The text-box check uses UI Automation. Terminals, VS Code and a few other editors don't report a text box to Windows, so there a double tap always writes (always_write_in in the settings). Rewriting the selection has its own key (§9.2). Otherwise MWB writes.
  5. Clean-up rules, under 5 ms: drop fillers, collapse stutters, turn spoken commands into punctuation, apply your dictionary. Parakeet already outputs punctuation and capitals.
  6. Optional polish by a language model, chosen per app. Through the API it adds under a second; on the local fallback, 1 to 3 s. It is off by default on the Lean profile, because it sends what you dictated to the API; hold Shift as you finish to ask for it. Not built yet: it comes with the per-app style (DIC-4) in Phase 5.
  7. Insert. Save the clipboard, put the text on it, send Ctrl+V, and restore the clipboard 400 ms later (P0-2 pasted reliably with 400 ms). MWB's text is marked to stay out of the clipboard history (Win+V), and the clipboard is put back only if nothing else changed it meanwhile. When the clipboard holds something other than text, such as an image or copied files, or the app is on the type_instead list, the text is typed with SendInput instead, so nothing you copied is lost.
  8. Log the text, the program it went into (never the window title) and the latency to the history table, for search. The tray's "Copy last dictation" gets the last one back. MWB's log files record only lengths and timings, never the words.

9.2Voice commands on selected text

Select text anywhere, hold Ctrl+Alt+R, and say what you want: "shorter", "more formal", "turn this into bullet points", "translate to Hindi". MWB copies the selection, restoring your clipboard afterwards, transcribes the instruction, asks the language model to rewrite, and shows the result in a panel that rises out of the indicator, with Copy and Replace. The panel never takes the keyboard focus, so the selection is still there for Replace. A quick press without speaking shows a short hint.

Through the API, rewriting a paragraph takes 1 to 2 s. On the local fallback it takes roughly 5 to 15 s on this laptop, so the result streams into the panel as it is written; the second memory stick makes that about twice as fast.

9.3Meetings

Any video-call app, desktop or browser. Detection does not depend on one vendor. Every 5 seconds the core asks Windows which apps are using the microphone right now. Windows records when each app last started and stopped using the mic, both for packaged apps such as new Teams or WhatsApp and for desktop programs such as Zoom.exe or slack.exe. A stop time of 0 means the app is using the mic at this moment. Reading these keys takes microseconds and needs no admin rights. On this laptop, keys already exist for new Teams, Edge and Wispr Flow.

sensors/meeting_detector.py (simplified from the built code)
import winreg

MIC = r"Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\microphone"

def mic_holders() -> list[str]:
    """Every app using the microphone right now, packaged or desktop."""
    found = []
    for path, packaged in ((MIC, True), (MIC + r"\NonPackaged", False)):
        with winreg.OpenKey(winreg.HKEY_CURRENT_USER, path) as root:
            for i in range(winreg.QueryInfoKey(root)[0]):
                name = winreg.EnumKey(root, i)
                if name == "NonPackaged":
                    continue
                with winreg.OpenKey(root, name) as k:
                    try:
                        start = winreg.QueryValueEx(k, "LastUsedTimeStart")[0]
                        stop = winreg.QueryValueEx(k, "LastUsedTimeStop")[0]
                    except FileNotFoundError:
                        continue
                if start and stop == 0:                  # 0 = still using the mic
                    # desktop apps are keyed by exe path with "#" for "\"; keep the exe name
                    found.append(name if packaged else name.split("#")[-1])
    return found   # e.g. ["MSTeams_8wekyb3d8bbwe"], ["Zoom.exe"], ["brave.exe"]

Each holder is matched against config/vc_apps.toml. MWB's own process is never a call, and nor are dictation apps and recorders such as Wispr Flow. When the holder is a browser, MWB reads the titles of that browser's windows, only at that moment, and looks for a known meeting site. A window title shows only the tab in front, so reading every tab through UI Automation is still to do. The camera key is recorded with the meeting, and the classic Outlook calendar item running within 10 minutes either side gives the meeting its subject.

  • Start: a known call app holds the mic for 20 s or more, or an unknown one does and you say yes. If a classic Outlook calendar item is running within 10 minutes either side, its subject becomes the meeting's title; MWB may start Outlook for this (decision 4). The organizer and attendees are left for the journal (Phase 4).
  • Asking first: during the first week MWB asks before every recording, and apps marked personal, or with the policy "ask", always ask. A small card appears at the bottom right: "Teams is using the microphone. Record this call?", with Record, Not this one, and Never for Teams. It never takes the keyboard focus, so your typing in the call goes on. No answer within 2 minutes means "Not this one".
  • On start: the notification "Recording Sprint review (Zoom). Press Ctrl+Alt+M to stop.", and the tray icon and the indicator get the orange ring. Ctrl+Alt+M also starts a recording by hand.
  • Two lanes: You (mic) and Them (system loopback), each with AI-App's VAD and gain levelling; echo is removed when the lanes are merged. Loopback hears every app the same way, so no app needs special support. Windows sends loopback audio only while something plays, so the recorder fills the gaps with silence from the clock and both lanes keep one timeline. Later, Windows' per-process loopback can capture only the call app's audio, whichever app it is.
  • During the call: each lane is cut at pauses into pieces of 22–28 s, which are written to %LOCALAPPDATA%\MWB\audio\m<id> as temporary WAV files. whisper small transcribes each piece with one whisper-cli run: 2 threads, below-normal priority. This happens live only on mains power and while the CPU hasn't stayed above 80 % for 30 s. On battery, or with a busy CPU such as video and screen sharing, the pieces wait and are transcribed after the call with 4 threads. Each piece is deleted the moment it is transcribed, and pieces left by a crash are picked up at the next start.
  • The end: the mic is released for 60 s, or you press Ctrl+Alt+M. When the last piece is done, the lanes are merged into one timeline marked You and Them, echo is removed, and "Transcript ready: Sprint review · 45 min. Press Ctrl+Alt+J to open it." appears.
  • After the call: write notes for each 10-minute chunk, combine them into one summary, pull out decisions and action items with owners, then classify (§10). Owners and deadlines are copied as said ("by Friday"); the date is worked out by code from the meeting's day, because the models got dates wrong in P0-4. With only two lanes MWB can't tell the other speakers apart, so their action items are owned by "Them" until diarization arrives.
  • No recording needed: if the platform already transcribed the meeting (Teams, Zoom cloud recordings, Google Meet, Webex), the tray's "Import a transcript…" reads its .vtt, .docx or .txt file instead. It costs no CPU, nothing is recorded at all, and the meeting gets the same notes and label.

9.4Email

Explain: press Ctrl+Alt+E

Works on selected text in any mail client, including your work mail in Outlook on the web in Edge. When classic Outlook is in front and nothing is selected, it reads the open or selected message directly. The panel shows a short summary, what they want from you, deadlines as real dates (worked out by code), the people involved, and reply ideas.

Draft: hold Ctrl+Alt+E and speak

Say the gist: "tell him I'll share the build by Wednesday and I still need Kafka access". MWB writes the reply in your style and shows it in the result panel with Copy, Insert, and, when the email came from classic Outlook, Open as Outlook draft for you to edit. It never calls Send, and a test checks every line of MWB's code for that.

Your style card. Once, at night on the local model, MWB reads up to 30 of your sent emails and writes a short card: greeting, sign-off, typical length, tone and phrases you use. Those emails are not uploaded. Drafts then use the card plus the thread, through the API like the rest of the email skill. Your sent work mail is only in Outlook on the web, so the style card waits for your choice on how MWB may read it (decision 4).

COM works with classic Outlook, which is installed with one profile and holds your meeting calendar. Your work account is on Microsoft 365 and only in Outlook on the web, and new Outlook has no COM, so there MWB works from selected text. A Microsoft Graph connection is a later option; it needs an app registration that IT approves.

9.5Code

Select code anywhere and press Ctrl+Alt+K. The panel shows what the code does, problems (bugs, edge cases, complexity), an optimised version as a diff, and tests if you ask. Its buttons are Copy, Replace selection, and Open diff in VS Code (code --diff). MWB guesses the language from the window title, for example main.js - AI-App - Visual Studio Code. Hold the same keys for a moment (0.35 s or more) and describe what you need, such as "a Java method that retries with exponential backoff", and the code is pasted at the cursor. MWB never runs code that a model wrote.

Through the API, gpt-oss-120b explains code and suggests optimisations quickly. The local fallback for code is Qwen3.5 4B with thinking off; it explains code well and handles small refactors. For large changes, Claude Code or Copilot in the editor is the better tool. On the Performance profile a 30B mixture-of-experts coding model runs locally.

9.7Ask MWB: answers by voice

The same double tap of Caps Lock answers questions. MWB treats what you said as a question when the cursor is not in a text box, or when you start with the wake word, "MWB" by default. You can change the word, or make the double tap always write or always answer.
