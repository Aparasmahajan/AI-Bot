17Plan

Six phases over about seven weeks. Each phase ends with a check you can run, and nothing moves on until that check passes. Estimates assume one developer working part-time with an AI coding assistant; double them for evenings only.

Estimates move with scope, and Rev B re-estimated them. Covering every video-call app instead of Teams alone added two days to P2. The effort governor and automatic re-tuning on another laptop added two days to P5. Rev C added one more day to P5 for the setup screen where you choose the effort. Rev D added three days: one each for the double-tap trigger with the first indicator skin (P1), answer mode (P3), and the remaining skins with their settings (P5). Rev E changes no dates: an API check replaces the local bake-off in P0-4, and the router with its local fallback replaces the local-only language worker in P3.

P0 · Spikes and calibration

days 0–3

  • P0-1 Two-lane capture in Python on this laptop with PyAudioWPatch, and soundcard only if it fails. Ten minutes of mic plus loopback with no dropouts.
  • P0-2 RegisterHotKey hold-to-talk with release detection; paste into Outlook, Teams, VS Code and Brave. Double-tap detection for Caps Lock and Alt by a 15 ms check: catch rate, false starts, and Caps Lock state restored.
  • P0-3 Classic Outlook COM: read today's calendar and Sent Items subjects. Note any security prompt.
  • P0-4 API and fallback: Groq response times from your network and answer quality on the MWB tasks, then the same tasks on the Qwen3.5 2B and 4B fallback with the llama.cpp already installed, CPU against Vulkan. This is the first sync check. Their speeds are already measured (§12.3).
  • P0-5 Mic-usage detection on real calls in Teams, Zoom, Google Meet in Brave, Webex and a Slack huddle. Confirm the exe and package names in vc_apps.yaml.
  • P0-6 Hardware fingerprint and a first calibration run on this laptop, saved as the Lean baseline.
  • P0-7 Your own voice: 20 work sentences recorded on your headset, through Parakeet and whisper. Word error rate against the 10 % limit in §7.2, plus Hinglish sentences if decision 5 needs them. The first benchmark used a synthetic voice, so it was a best case.

ExitNumbers written to docs/bench/, a go or no-go for each choice, and the estimates in this document replaced by measured values. No colleague is recorded in Phase 0: call audio comes from test calls and played videos.

P1 · Dictation MVP

days 3–11

  • Core: single instance, event loop, tray, hotkeys, supervisor, memory guard v0, SQLite schema.
  • Speech worker: port AI-App's server.py; add /health, /shutdown, thread and arena flags.
  • Dictation: double-tap Caps Lock and push-to-talk, load on start, transcribe while talking, clean-up rules, dictionary, paste, history.
  • Indicator v1 with the Capsule skin and the double-tap Alt toggle.

ExitFinish-to-text at most 1.0 s median for phrases up to 10 s; core at most 60 MB idle; worker exits after 15 idle minutes; works in five target apps; Caps Lock left unchanged after double taps; the indicator never takes focus. Wispr Flow can be switched off.

P2 · Meeting capture

days 11–20

  • App-agnostic meeting detector with vc_apps.yaml, browser tab matching, camera and calendar-link signals, and a recording policy per app.
  • Two-lane recorder, low-priority transcription in 10-second pieces, CPU back-off with a disk queue.
  • Storage of segments, transcript import for Teams, Zoom, Meet and Webex, a meeting list in the Today page.

ExitDetects at least 95 % of a week's calls across every app you use; personal apps always ask; transcript ready within 2 minutes of the end; no audio kept unless asked.

  • API client and router with the local fallback and the weekly sync check; meeting notes in two passes; action items with owners.
  • Work/Timepass stages A to C; email explain and draft; code explain and optimise; rewrite by voice.
  • Answer mode: write-or-answer decision, wake word, answer card, lookups in your own data with citations.

ExitNotes within 10 minutes of a 60-minute call; 80 % label agreement on your first 20 meetings; 10 questions about your day answered with correct facts; with the network off, every skill still answers through the fallback; no code path that sends mail.

P4 · Daily journal

days 30–37

  • Git, activity, Outlook and calendar collectors; day composer with fact rendering and cited narrative; validator.
  • Today page, 18:30 reminder, Markdown export, Outlook draft.

ExitJournal within 5 minutes on Lean; every SHA correct; every narrative sentence linked to an event.

P5 · Profiles, effort and hardening

days 37–48

  • Profile detection, calibration and the hardware fingerprint; per-machine settings kept apart from yours; models.yaml downloads with confirmation.
  • Setup screen on first start: hardware summary, suggested effort, your choice of a fixed level or an automatic range, battery behaviour and per-feature levels, then the model list.
  • Effort governor E1 to E4 with the power, load and memory rules; the night second pass.
  • The other seven indicator skins, custom PNG skins, and the indicator settings (gesture, size, position, opacity, live words).
  • Settings, retention and privacy controls; crash recovery, logs, a portable build with the Start-menu shortcut key, user docs.

ExitA full week as your daily tool; a crashed worker recovers within 10 s; copying MWB to a second laptop opens the setup screen with that laptop's suggestion and keeps your choice for that machine only; with automatic adjustment on, unplugging the charger lowers the effort level within 30 s.

Later

after the POC

Diarization, live captions, search across history ("what did we decide about Kafka?"), Jira or Azure DevOps sync, weekly reports, GPU and NPU models, and a native C# shell if Python's footprint ever becomes the limit.

20Glossary

ASR
Automatic speech recognition. Speech in, text out.
WER
Word error rate: the share of words that come out wrong. Lower is better.
× real time (RTFx)
How many times faster than the audio plays. 5× means a minute of speech takes 12 seconds.
VAD
Voice activity detection. Finds where speech starts and stops, so only speech is transcribed.
Diarization
Working out who spoke when, and giving each speaker a label.
Loopback
Recording what your speakers play. In a call, that is the other side.
LLM
Large language model. Reads and writes text: summaries, drafts, labels.
Token
A piece of a word, about three quarters of an English word on average. Model speed is quoted in tokens per second.
Prefill and decode
Reading the prompt, which is fast, and writing the answer, which is limited by memory bandwidth.
Quantization
Storing a model's numbers in fewer bits (int8, 4-bit) so it uses less memory and runs faster, at a small cost in accuracy.
GGUF, ONNX
File formats for models. llama.cpp runs GGUF; ONNX Runtime runs ONNX.
Memory bandwidth, channels
How fast RAM feeds the CPU. Two sticks in two slots (dual channel) double it.
Working set, private bytes
RAM a process has in physical memory right now, against memory it has reserved, part of which may sit in the pagefile.
Arena
onnxruntime's memory pool. Fast, but it keeps memory after a large input instead of returning it.
Worker, sidecar
A separate process that does the heavy work and can be ended to free its memory.
mmap
Mapping a model file into memory, so Windows loads pages as needed and can drop them under pressure.
Few-shot
Putting a handful of examples in the prompt to steer the model, such as your past label corrections.
RAG
Retrieval-augmented generation. Search your own data first, then let the model answer from what it found.
VC app
Any video-conferencing or calling app: Teams, Zoom, Meet, Webex, Slack huddles, WhatsApp and others.
Effort level
How hard MWB works right now, from E1 to E4: threads, model size, extra passes, live features.
Hardware fingerprint
A short ID built from CPU, RAM, GPU and NPU. When it changes, MWB re-calibrates and re-tunes itself.
API key
A password-like token that lets MWB use a cloud model such as Groq or OpenAI. For now, MWB's main route for language work.
Fallback
The local model MWB uses when the API can't be reached, or for a skill set to local-only.
Sync check
Saved test prompts run through both the API and the local model, to make sure the fallback still gives usable answers in the same format.
Thinking mode
Qwen3.5 can reason step by step before it answers. That gives better answers but is much slower on a CPU, so MWB turns it off.
Double tap
Two quick presses of the same key within 350 ms: Caps Lock to talk or ask, Alt to show or hide the indicator.
Indicator
The small floating icon at the bottom of the screen that shows what MWB is doing, like Wispr Flow's pill.
Wake word
A word you start with, "MWB" by default, to make MWB answer instead of typing what you say.
Event loop
The part of the core that sleeps until something happens, handles it in microseconds, and goes back to sleep.
